# Filter the todo list

A user with a growing list can focus on what is left to do, or look back at what is done, without losing any todo.

## Clear

- Three views: all todos, only the active ones (not done), only the done ones.
- The chosen view is remembered in the same browser: a reload reopens it. A first visit, or an unreadable saved view, opens on "all".
- Ticking or unticking a todo in a filtered view moves it out of that view at once.
- A view with nothing to show says so, in words that name the view.
- Adding a todo while the "done" view is shown switches to "all", so the new todo is visible.
- Out of scope: counts, a "clear done" action, the view in the URL, keyboard shortcuts.
- Changed at the contract pause: the requester reloads often and wants the view kept.

## Assumed

- Deleting works the same in every view, since a todo is the same todo whatever the view.
- The view picker is a group of three buttons with the current one marked, the usual pattern for a small todo app.
